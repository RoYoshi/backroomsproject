# dev/tools/gate: the modernization gate

One command decides whether a checkpoint is still the accepted B++ game, on the modern layout:

```text
node dev/tools/gate/gate.js --tier fast --packages <folder> --out <scratch>/gate        # about 11 minutes: every deterministic comparison
node dev/tools/gate/gate.js --tier full --packages <folder> --out <scratch>/gate_full   # the final candidate: over an hour on 2 CPUs
# --packages (or TFB_CLIENT_PACKAGES): the 31 locked npm packages the client build installs offline (continuation C4); without them the
# port and bundle steps are NOT RUN, which is a FAIL
```

## How it decides

- **The reference is always the accepted B++ head** `143b63ff42b88c6780c5043e0f61d64100f81f40`, never the previous checkpoint.
- **The traces are compared with Stage 3H's stored B++ baselines,** byte for byte:
  - `dev/stage-3h/evidence/h1/golden/srv_traces` and `cli_traces`;
  - `dev/stage-3h/evidence/h2/golden/bpp_traces` and `cli_traces`.
- **A step passes only on its own positive evidence.** A step that compared nothing is a FAIL.

## What it cannot see

The `bundle` step's Chromium renders with SwiftShader (software WebGL, no physical GPU) and steps a virtual clock: it proves two builds draw, sound and behave the same frame by frame, not how the game looks or feels on a player's machine.

Stage 3H2's limits still apply (`dev/stage-3h/gate/README.md`, "What the gate cannot see"):
- real-browser timing beyond structure;
- pixels outside the contact lab's frozen scenes;
- sound heard rather than traced.

The `page` step's canvases and Graphics record every call; they draw nothing that is looked at. Two scripts that make the same calls
draw the same picture, but what that picture looks like is the contact lab's (for its scenes) and Human QA's.

B++'s `place_replay.js` can fail one case by chance, in about 7 % of runs (3H finding F-036): a glitched wall drawn on its walk takes
its mover out of the level. A failing case that sent no stale pose, got no correction and whose track stops early is that case; run
the step again (`dev/stage-3h/gate/README.md`, "What the gate cannot see").

The contact lab can differ by one level in a few pixels of `peers_visible.png`, on B++ as on the candidate (M-036): BR-RoLE eases a
light's weight on a body a fixed share a frame, and the lab captures after a wait in real time. If that image alone differs, by at
most one level, compare the two sides' `result.json` (`scenes.peers.visible.jobs[0].a`: the other player's cast, close to 0.5667 on both),
then run the step again (`--only contact_lab`) and report both runs. Any other image, or a larger difference, is a real one.

`two_browser.py` (the `browsers` step) fails when the watching page's frames are long, on M8's game as on the candidate's (M-037).
Its one-pose check samples Bob's drawing of Alice inside BR-RoLE's draw, which the compiled client calls before `mp.js`'s hook
moves the avatar; `mp.js` moves the drawn pose between frames when a newer pose is more than 96 px away (`PEER_SNAP`), and a
sprint carries it that far only when frames are long. So run nothing heavy beside the step: C5d's final gate failed it while a
build ran beside it (3 of 79 frames). If `two_browser` fails with Bob's frames long (`bobFrameMsMedian` well above the usual
130 to 200 ms), offsets above 96 px in a sprint or a run and the drawn pose on the newest one, run the step again alone (`--only
browsers`) and report both runs. Any other failure of the check is a real one.

The perf step can also fail by chance on a small machine (M-021). With seven rounds, the tolerance can fall to its floor (5 % for a
server scenario, 10 % for a page scene) while the two sides' medians differ by more than that, with nothing changed. Do not relax the
rule. Measure first. A server scenario: `node dev/stage-3h-modernization/tools/m1_perf_paired.js --work <empty scratch folder>
--scenario <the failing one>` runs 30 interleaved rounds on four sides and reports the paired change. A page scene: `node
dev/tools/gate/golden/perf_det.js --only client --rounds 21` times the page's scenes again, with more rounds (as C5 did). Then re-run
the step (`--only perf`), and report both runs.
