# The interface's sounds — asset list

Pre-Trial 3 polish P7. Seven short sounds for the menus and panels. They are **placeholders**: made so the interface has
quiet, consistent feedback now, and meant to be replaced by the game's sound designer, Mariikyu, at any time.

19,745 bytes in all. Full record (every hash, sample counts, first and last samples): `SOUND_ASSETS.json`.

- **Format:** MP3 (MPEG-1 Layer III), mono, 44.1 kHz, 96 kbit/s CBR, no ID3 tags; the LAME header is kept so browsers trim the
  encoder's padding. 44.1 kHz is the menu audio's own rate, so nothing is resampled.
- **Origin:** programmatically synthesized placeholders — sine waves, simple envelopes and seeded noise, by
  `tools/ui_sounds.py` (numpy, then ffmpeg 6.1.1 with libmp3lame). Nothing sampled; nothing taken from any game, library, preset or
  other recording.
- **Ownership / licence:** original files generated by this repository's own script for The Far Backrooms; no third-party audio.
  They are the project's own assets like its other original files — the owners decide their terms. (No licence statement is
  claimed for them here.)
- **Sound:** soft, short and quiet; slightly uneasy rather than cheerful (the panel-opening sound is a low hum beating slowly
  against itself, like a tube warming, with two faint ticks). Each is mastered at its intended loudness relative to the others —
  the hover tick about 12 dB under a click — and starts and ends on silence (raised-cosine fades, each layered part with its own
  fade-out, so no click at a joint). **How loud they really feel is for a human to judge** (`HUMAN_QA.md`).

## How the game plays them

`src/frameworks/front/client/ui.js` (built to `public/assets/ui.js`):

- One audio context — the main menu's own (the menu music's). The sounds are decoded once, when the menu first appears, and play on
  a **UI gain** under the **master gain**, beside the music's gain:
  `music → music gain (0.7 × Music volume) → master (Master volume, 0 while SOUND is off) → speakers` and
  `interface sounds → UI gain (UI volume) → master` (Music volume and UI volume: Settings → Sound, added at P8; 100 % until set).
- One listener for the menus and panels (the main menu, Settings / Credits / Help, Customize, the pause and run menus) decides
  which sound a press makes, so a press makes one sound, never two. Only real presses count (a script's `click()` makes none). Typing,
  the sliders and the chats (they have their own voices) make none.
- Nothing is started while SOUND is off, a volume on its way is 0, or the tab is hidden. A press may wake the context (a press is the
  gesture browsers ask for); a hover only plays while it is already running. The context sleeps again a moment after the last sound
  when no music plays.
- Interface sounds are this page's own: never sent to other players, never placed in the world.

## Replacing one

1. Make the new sound (MP3 suggested; mono, 44.1 kHz; trimmed; starting and ending on silence; peak well under full scale).
2. Save it over the file of the same name in `public/assets/` (for example `public/assets/ui_click.mp3`). Keep the name.
3. Reload the game. Nothing else needs to change; set its loudness by the file itself (the game adds only the UI and master volumes).
4. `python3 -I -B dev/pre-trial3-final-polish/tools/ui_sounds.py check` will then report that the file is no longer the inventoried
   placeholder — expected after a replacement; regenerate the record with your files or retire the check.

To make the placeholders again exactly: `python3 -I -B dev/pre-trial3-final-polish/tools/ui_sounds.py make`
(the render is deterministic; `check` confirms the recipe and the files still match this record).
