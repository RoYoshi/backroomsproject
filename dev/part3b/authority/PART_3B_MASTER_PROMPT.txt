==================================================
1. PART 3B GOAL
==================================================

Make 2.5D HEIGHT FEEL VISIBLE.

The current engine knows physical Z, but falling/stairs can still feel visually static.

Part 3B must add presentation depth without changing simulation:

- camera follows local player presentation Z smoothly,
- lower layers subtly recede/shrink when the player is above them,
- destination surfaces approach during a fall,
- restrained vertical parallax,
- smoother stair/ramp visual motion,
- restrained landing response,
- safe hand/body vertical secondary motion where useful,
- correct inverse/projection-aware picking,
- correct cutaway/roof semantics.

Core law:

`SIMULATION TRUTH != PRESENTATION INTERPRETATION`

==================================================
3. CAMERA Z
==================================================

Implement an explicit presentation camera elevation state.

Use time-based stable smoothing (critical spring or equivalent), not a fixed per-frame
lerp percentage.

Requirements:
- smooth real-time behavior across render FPS/jitter,
- no tread-by-tread camera snapping,
- sufficient response to make large falls feel vertical,
- bounded lag,
- safe snap/reinitialize on teleport/respawn/reconnect/world reset.

The local player remains the presentation reference plane.

==================================================
4. DEPTH ILLUSION
==================================================

Implement restrained camera-relative elevation projection.

When geometry is below the local player's presentation plane:
- it should become slightly smaller/more distant,
- XY displacement may contract subtly around camera center.

As the player falls toward it:
- that surface approaches normal reference scale smoothly.

One major 180-unit elevation should initially produce only a subtle visual difference
(roughly a few percent, not dramatic perspective).

Clamp the effect.

This remains top-down/Surviv.io-like, not a perspective 3D camera.

==================================================
5. FAIRNESS LOCK
==================================================

Depth projection MUST NOT expose more world.

The existing canonical camera-policy world footprint remains the admission budget.

Do not render actionable actors/geometry outside the world footprint merely because
a lower plane shrank in screen space.

Ultrawide, DPR, UI scale and quality must not provide extra tactical awareness.

DPR is sharpness only.

==================================================
6. FALL / LANDING
==================================================

Prove:
- +180 -> 0 fall,
- 0 -> -96 fall.

Without HUD/debug, descent should read visually.

Use:
- camera elevation response,
- destination-floor approach,
- relative layer parallax/scale,
- restrained actor/hand inertial motion,
- small landing settle if useful.

Do not add large aim-disrupting shake.

==================================================

LONG ROOM stairs are a primary validation scene.

Physical treads remain exact.

Visually:

Ramps remain physically continuous and should present continuously.

==================================================
8. CUTAWAY / ROOF SEMANTICS — USER CORRECTION
==================================================

The current broad room-roof interpretation is NOT the intended final behavior.

Level 0 is one continuous interior.

Ordinary rooms and hallways must remain continuously visible.

Do NOT black out/hide an ordinary Level 0 room until the local player enters it.

A normal Level 0 ceiling is physical simulation geometry but is NOT automatically a
Surviv.io building roof.

Distinguish presentation semantics:

### Continuous interior ceiling
Physical for collision/AI/light/sound.
Does not act as a room-entry roof mask for the top-down player camera.

### Local cover
Crawlspace/hide-under/under-platform structure.
Outside viewer may have the covered interior concealed.
Local player underneath receives only the local necessary reveal.

### Overlap slab
Real upper floor over lower walkable space.
Local lower player may cut away the blocking slab/group.
Unrelated geometry remains visible.
Other clients retain independent local views.

### Building roof
Reserved for a FUTURE genuinely separate building, especially exterior -> interior.
Do not implement future levels/buildings now.
Only keep the semantic distinction if useful to the architecture.

- nearby ordinary Level 0 room remains continuously visible.

Two clients must have independent cutaway state.
