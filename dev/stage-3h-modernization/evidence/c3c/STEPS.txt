## the modules (by hand, from M8's parts: what moved where is in the module headers, docs/architecture/CONTRACTS.md section 4 and ADR-005)
  mp.js's 16 parts at M8 became 11 modules and a composition (src/core/client/mp.compose.js), one module per owner, the parts of one
  owner that shared state merged (B++'s net, newrun and transport: mp.session.js; G.I.B.'s own death, bodies and replays: mp.deaths.js;
  OVERSEER's admin and death lab: mp.admin.js); src/build-recipes.json lists the 12 parts in the order they run:
    core = mpCore(); session = bppSession({ core }); glitch = lostGlitch({ session }); cartograph = pocketCartograph({ session });
    monsters = naniMonsters({ core, session, glitch, cartograph }); space = spacePeers({ session, glitch }); audio = audioDread();
    wanderers = brrWanderers({ session }); deaths = gibDeaths({ core, session, monsters, wanderers });
    admin = overseerAdmin({ core, session, glitch, cartograph });
    mpFrame({ core, session, glitch, cartograph, monsters, audio, deaths, admin });
    session.wire({ glitch, cartograph, monsters, space, wanderers, deaths, admin });
  State declared by the owner its meaning gives (the session's state from core to B++; the entity slots, the kill record and killer, the
  held state and the fails to N.A.N.I.; the exit flag to L.O.S.T.; the cartograph's globals to P.O.C.K.E.T.; the admin panel's state to
  OVERSEER; the last view to G.I.B.; the heartbeat's timer to the per-frame hook; the status line and the network send to B++; the peers'
  network record and the world epoch from S.P.A.C.E.'s part to B++).  Every write across owners is a call of the owner's function, in the
  same place; every read of a changing value a reader the owner gives (me(), snap(), exited() ...): the same value at the same moment.
  The session handles every message and so calls functions of modules made after it: those are its late names (rule 12), declared
  without a value and given once by wire(), which the composition calls when every module is made.  Construction keeps M8's order of
  load effects (ents' onFail, the WebSocket, the dread's listeners, the wanderers' pointer listener and interval, the admin panel's DOM,
  listeners and intervals) and window.__net's keys in M8's order.

  C3c, for every page script: a mutating call (set, delete, clear, add, push, pop, shift, unshift, splice, fill, sort, reverse,
  copyWithin) is a write like an assignment; an object a module reaches through the global object (window.X, or a name given its value
  from one) is written, property by property, by one module, and only by X's owner; one module assigns each global name; rule 12, late
